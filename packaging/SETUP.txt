Exercise 2 - week 1 setup
=========================

STEP 0 - DELETE THE OLD CONSOLE UI FIRST
----------------------------------------
In IntelliJ delete this whole package:

    ui\src\guessmarket\ui\console

It will not compile any more. EventDto gained new fields, Event is now
created through Event.lmsr(...) and Event.orderBook(...), and events start
"not started" instead of active. Exercise 2 is a JavaFX application, so the
console UI is not needed.

STEP 1 - EXTRACT
----------------
Extract this zip over  C:\CS_Degree\JAVA\GuessMarket  and replace.
It overwrites the engine and adds ui\src\guessmarket\ui\fx.

STEP 2 - JAVAFX SDK
-------------------
Download the JavaFX SDK for Windows x64 from https://gluonhq.com/products/javafx/
Pick the version matching your JDK (25, or 21 LTS). Extract to somewhere
permanent, for example:

    C:\CS_Degree\JAVA\javafx-sdk-25\

Copy the jars from  javafx-sdk-25\lib\  into a new folder in the project:

    C:\CS_Degree\JAVA\GuessMarket\lib-fx\

Keep them separate from lib\ so it stays obvious which jars are which.

STEP 3 - ADD THE LIBRARY
------------------------
File -> Project Structure -> Libraries -> + -> Java
Choose  C:\CS_Degree\JAVA\GuessMarket\lib-fx
When asked which module, tick  ui  only. Not engine.
Apply, OK.

STEP 4 - RUN CONFIGURATION
--------------------------
Run -> Edit Configurations -> + -> Application
    Name:        Guess Market FX
    Module:      ui
    Main class:  guessmarket.ui.fx.GuessMarketApp

Then "Modify options" -> tick "Add VM options", and paste:

   --module-path "C:\CS_Degree\JAVA\javafx-sdk-25\openjfx-25.0.4_windows-x64_bin-sdk\javafx-sdk-25.0.4\lib" --add-modules javafx.controls,javafx.fxml

Adjust the path if you extracted the SDK elsewhere.

STEP 5 - RUN
------------
The window opens with "Guess Market" at the top, a Load File button, and two
tabs which stay greyed out until a file loads.

Load  samples\small.xml  - two events and three users.


IF IT DOES NOT START
--------------------
"JavaFX runtime components are missing"
    The VM options in step 4 are missing or the path is wrong.

"app.fxml was not found"
    The fxml files are not being copied into the build output.
    File -> Settings -> Build, Execution, Deployment -> Compiler
    Check "Resource patterns" includes  !?*.java
    Then Build -> Rebuild Project.

"LoadException" / "Cannot load fxml" with a long stack trace
    Read the "Caused by" line at the BOTTOM of the trace, not the top.
    It names the exact fx:id or method that does not match.
